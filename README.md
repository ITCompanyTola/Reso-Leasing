# Новогодний вечер РЕСО-Лизинг — Вечер кинопремьер

Одностраничный сайт-приглашение (23.12.2026, 17:00, Triumph Event Hall). Статический сайт: нет сборки, сервера приложений и зависимостей от сторонних сервисов.

## Что в архиве

```
index.html                 страница (лежит в корне — так нужно для GitHub Pages)
assets/css/style.css       стили и анимации
assets/js/config.js        НАСТРОЙКА ФОРМЫ: адрес обработчика заявок
assets/js/app.js           логика страницы (таймер, форма, пасхалки, эффекты)
assets/js/runtime.js       мини-рантайм шаблона
assets/js/morphdom.min.js  библиотека morphdom (MIT), лицензия рядом
assets/fonts/              шрифты Cormorant Garamond и Marck Script (SIL OFL 1.1)
assets/img/                изображения
.nojekyll                  отключает обработку Jekyll на GitHub Pages
.htaccess                  настройки для Apache-хостинга (GitHub его игнорирует)
docs/nginx.conf.example    пример настройки для nginx
```

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Загрузите в него **содержимое** папки `reso-leasing-party` — так, чтобы `index.html` лежал в корне репозитория, а не во вложенной папке.
   - Через сайт: «Add file → Upload files», перетащите все файлы и папки **изнутри** `reso-leasing-party` (скрытые `.nojekyll` и `.htaccess` на macOS показываются по Cmd+Shift+.).
   - Через терминал, находясь в папке `reso-leasing-party`:
     ```
     git init
     git add .
     git commit -m "Лендинг: новогодний вечер РЕСО-Лизинг"
     git branch -M main
     git remote add origin https://github.com/<аккаунт>/<репозиторий>.git
     git push -u origin main
     ```
3. Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)` → Save.
4. Через 1–2 минуты сайт откроется по адресу `https://<аккаунт>.github.io/<репозиторий>/`. Пути относительные, поэтому работа из подпапки поддерживается.

**Свой домен.** Settings → Pages → Custom domain → впишите домен и сохраните (GitHub создаст файл `CNAME`). У регистратора домена добавьте DNS-записи по инструкции GitHub (A-записи на адреса GitHub Pages или CNAME на `<аккаунт>.github.io`). Когда домен проверится, включите «Enforce HTTPS».

**Другой хостинг.** Загрузите эти же файлы в корень сайта (`public_html/` или `www/`). Для Apache уже есть `.htaccess` (сжатие, кэш, заготовка редиректа на HTTPS), для nginx — `docs/nginx.conf.example`.

Проверка на своём компьютере: в папке выполните `python3 -m http.server 8000` и откройте http://localhost:8000.

## Форма регистрации — обязательно до публикации

Сейчас в `assets/js/config.js` адрес обработчика пустой, поэтому форма **честно** сообщает: «Регистрация пока недоступна…». Ложного «Вы зарегистрированы!» больше нет.

```js
window.RESO_CONFIG = {
  endpoint: 'https://адрес-вашего-обработчика',  // POST, JSON
  timeoutMs: 15000
};
```

Форма отправляет `POST` с заголовком `Content-Type: application/json` и телом:

```json
{ "fullName": "Смирнова Анна", "department": "Департамент продаж", "createdAt": "2026-11-26T10:00:00.000Z" }
```

Успех — любой ответ с кодом 2xx. На ошибку сервера, обрыв сети, отсутствие интернета и тайм-аут форма показывает понятное сообщение, сохраняет введённые данные и даёт отправить ещё раз. Повторное нажатие во время отправки заблокировано.

Если обработчик на другом домене (Google Apps Script, CRM, свой сервер), он должен разрешать CORS-запросы с домена сайта: отвечать на `OPTIONS` и отдавать `Access-Control-Allow-Origin: https://ВАШ-ДОМЕН` и `Access-Control-Allow-Headers: Content-Type`. Иначе браузер заблокирует отправку и гость увидит сообщение об ошибке.

`config.js` отдаётся с `Cache-Control: no-cache`, поэтому изменения адреса применяются сразу.

**Персональные данные.** Форма собирает фамилию и имя сотрудника. Уточните у юриста, нужны ли по 152-ФЗ чекбокс согласия и ссылка на политику обработки данных (по просьбе заказчика их на странице сейчас нет).

## После подключения домена

В `index.html`, в блоке `<head>`:

- `og:image` — замените на абсолютный адрес: `https://ВАШ-ДОМЕН/assets/img/og-image.jpg`. Без этого превью в Telegram, WhatsApp и VK может не показаться.
- Добавьте `<link rel="canonical" href="https://ВАШ-ДОМЕН/">` и `<meta property="og:url" content="https://ВАШ-ДОМЕН/">`.
- Если приглашение не должно попадать в поисковики, замените `<meta name="robots" content="index, follow">` на `noindex, nofollow`.

## Обновление сайта

CSS и JS подключены с меткой версии (`style.css?v=…`), поэтому их можно надолго кэшировать в браузере. Если правите `style.css` или `app.js` вручную, поменяйте метку `?v=` в `index.html` на любую новую, иначе посетители увидят старую версию до истечения кэша. `config.js` и `index.html` не кэшируются.
